# Спецификация: свободный ввод, голосовой inbox и дневник (`/diary`)

Цель: принимать обычную человеческую речь (текстом или голосом) без специального синтаксиса, безопасно сохранять сырой ввод, различать намерения и давать быструю отмену или правку ошибок.

## Принципы
- Женский род, короткие ответы без «простыней».
- Сырой текст и аудиосообщение сохраняются в SQLite (`inbox_messages`) **до** обращения к STT/LLM.
- Повторная доставка апдейта Telegram идемпотентно игнорируется без дубликатов.
- Мысль, усталость или мечта («хочу когда-нибудь…») не становятся задачей или напоминанием автоматически (`_apply_guardrails` в `services/inbox_parser.py`).
- Вычисление дат/времени выполняется кодом Python по часовому поясу пользователя; неоднозначные формулировки («завтра в 8», «потом») не создают преждевременное напоминание, а запрашивают 1-клик уточнение.
- Слова пользователя (`user_text`) и заметки модели (`model_note`) хранятся раздельно.

## Куда попадают элементы
- `task` → `day_plan_items` (план дня на текущую локальную дату).
- `reminder` → `custom_reminders` (после детерминированного вычисления даты/времени) или `pending_clarification` до ответа пользователя.
- `shopping` → `shopping_list` (household-список покупок с единицами измерения).
- `diary` / `idea` / `done` → `journal_entries` (доступно в `/diary`).

## Правка, отмена и дневник
- Под каждым разобранным сообщением есть кнопки:
  - `✏️ Исправить` — сменить тип пункта (`Задача` / `Покупка` / `Дневник` / `Идея` / `Сделано`), отредактировать текст или удалить отдельный пункт;
  - `↩️ Отменить всё` — откатить все созданные этим сообщением записи;
  - `🔁 Переразобрать` — повторно прогнать разбор, если модель была недоступна.
- Команда `/diary` (и `/diary <запрос>`): вкладки `Дневник`, `Идеи`, `Сделано`, `Сырые`, поиск по подстроке, экспорт личных записей в JSON и двухшаговое удаление данных.

## Конфигурация LLM
- Настраивается через `.env` (`LLM_ENABLED`, `LLM_PROVIDER`, `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_PROXY_URL`, опционально `LLM_FAILOVER_*`).
- Идентификатор модели никогда не угадывается по разговорному названию и задаётся явно в env.
- При отключении или сбое модели бот продолжает работать на детерминированном fallback-разборе без потери данных.
