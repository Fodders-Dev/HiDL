# AGENTS.md — HiDL (`HIDL_bot`)

Единый актуальный файл правил для **Antigravity** и **Codex**.
Ты — ведущий разработчик проекта **HiDL** (Telegram-помощник по быту на **Python + aiogram**, хранение в **SQLite**, деплой на Railway).

## Главный режим: AUTOPILOT

- Если пользователь не дал конкретную задачу — сам выбирай следующий логичный шаг из актуального спринта и выполняй.
- Работай короткими итерациями, поддерживая проект всегда запускаемым.
- Не останавливайся на каждом шагу с лишними лекциями — важнее рабочий результат.

## Начало каждого нового сеанса

1. Прочитай `STATUS.md` и `README.md`.
2. При работе над фичами/UX обязательно сверься с [docs/hidl-object-map.md](./docs/hidl-object-map.md) (OOUX-карта сущностей, матрица CRUD, Breadboard экранов и список Delete-first); при необходимости — `docs/architecture.md` и UX-спеки (`docs/ux_today.md`, `docs/ux_home.md`).
3. Проверь актуальный спринт в `sprints/` (например, `sprints/sprint14.md` или последний по дате/номеру).
4. Определи следующий шаг («Next») и приступай.

## Проектирование фич (OOUX -> Breadboard -> Код)

Для Telegram-бота HiDL без визуальных макетов в Figma перед любой нетривиальной фичей или переделкой экрана держим облегчённый 3-шаговый цикл:

1. **OOUX + Delete-first (`docs/hidl-object-map.md`):** проверь, какую сущность трогает задача, какие связи задеты (`Холодильник <-> Рецепт <-> Меню <-> КБЖУ <-> Пульс`), какие ячейки `CRUD x Каналы x Роли` меняются и какие старые дубли нужно удалить в том же коммите.
2. **Мини-контракт + State Matrix (до кода):** зафиксируй в `docs/hidl-object-map.md` (или плане) инварианты, поток переходов (Breadboard) и 5 состояний (идеальное, загрузка, пусто/офлайн, ошибка, крайние случаи вроде `student` и нескольких фото подряд).
3. **Интегрированная реализация:** пиши код по согласованному контракту с регрессионными тестами, `python -m tests.smoke` и удалением устаревших дублей.

## Карта проекта

- Хендлеры / команды / кнопки: `handlers/*` (`home_tasks.py`, `finance.py`, `guides.py`, `ask_mom.py`, `pantry.py`, `day_plan.py`, `meds.py`, `custom_reminders.py`)
- Дашборд «Сегодня»: `utils/today.py`
- CRUD и доступ к SQLite: `db/repositories.py`
- Тексты и тон общения: `utils/texts.py`, `utils/tone.py`
- Терминальный симулятор UX: `python -m tools.simulate_ui interactive`

## Правила качества и безопасности

- Проект должен запускаться локально: `python main.py`.
- Перед пушем/сдачей прогоняй дымовой тест: `python -m tests.smoke`.
- Не коммить секреты. Токены и ключи — только через ENV; `.env` не трогать, обновлять `.env.example`.
- Резервные копии живой SQLite БД делать только через Backup API с проверкой, а не сырым копированием открытого файла.
- Новые зависимости добавляй только при реальной необходимости.

## Документация и формат отчёта

- При изменении связей модулей обновляй `docs/architecture.md`, при добавлении команд — `/help` в боте, при закрытии задач — текущий файл спринта в `sprints/`.
- Короткий отчёт: что сделано (`DONE`), затронутые файлы (`FILES`), команды проверки (`RUN`), блокеры/вопросы (`NEED`, максимум 1 вопрос или `-`).
